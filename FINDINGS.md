# Findings — first run, 2026-11-11

Four issues worth filing upstream. Each has a reproduction; none is a complaint
without an artifact.

Environment: Node v24.21.0 · `pdf-lib` 1.17.1 · `@cantoo/pdf-lib` 2.11.1 ·
`pdfkit` 0.15.2 · referee `pdfjs-dist` 4.10.38 · font `Arial` (Unicode coverage:
Latin, Greek, Cyrillic, Arabic, Hebrew, Vietnamese — **not** CJK, Devanagari, Thai).

---

## F1 — `pdfkit`: right-to-left text is extracted in the wrong order

**Severity:** high for anyone generating Hebrew/Arabic documents, invisible without
a round-trip test.
**Where:** `pdfkit` 0.15.2, embedded TTF, `doc.text('مرحبا بالعالم')`.

All codepoints survive but they come back reordered. `pdf-lib` and
`@cantoo/pdf-lib` return the same string; `pdfkit` does not shape or apply bidi.
For a document, reordered RTL text is a corrupted document — and it looks fine in
a viewer that does its own bidi, which is why it goes unnoticed.

**Reproduce:** `node src/cli.js --font ./Arial.ttf`, see the `order` cells in the
Arabic/Hebrew rows for `pdfkit` only.

---

## F2 — `@cantoo/pdf-lib`: font subsetting crashes with the standard fontkit

**Severity:** high — either a hard crash or a 65x file-size regression.
**Where:** `@cantoo/pdf-lib` 2.11.1 + `@pdf-lib/fontkit` 1.1.1,
`doc.embedFont(bytes, { subset: true })`.

```
TypeError: Cannot read properties of undefined (reading 'pos')
```

With `subset: false` it succeeds and writes **614.9 KB** for a one-page document
where `pdf-lib` 1.17.1 writes **9.4 KB** for the same content and the same
embedding call. The fork declares no fontkit dependency of its own, so this is the
pairing that every migrating user gets by default.

**Reproduce:** `node src/cli.js --font ./Arial.ttf`, "font subsetting" row.

**Open question for the maintainer:** is a specific fontkit version required, and
should it be declared as a dependency or peer?

---

## F3 — Silent text corruption: default fonts destroy non-Latin input without error

**Severity:** high. This is the mechanism behind the whole class.
**Where:** `@cantoo/pdf-lib` 2.11.1 and `pdfkit` 0.15.2, default font.

`pdf-lib` throws `WinAnsi cannot encode "م" (0x0645)` — noisy, and therefore safe.
The fork and `pdfkit` accept the same string and emit a PDF whose text is
destroyed on read-back. A user sees empty boxes on a printed invoice; nothing in
the pipeline logged a warning.

**Ask:** emit a warning (or throw) when a glyph is not representable in the
selected font. Silent loss should not be the default for text input.

---

## F4 — No JS PDF library can emit an accessible document

**Severity:** high for anyone under a document-accessibility obligation.
**Where:** all three libraries, every version tested.

None emits `/StructTreeRoot`, `/MarkInfo`, `/Lang`, `/Title` or `/Alt`, and none
exposes a tagging API. `pdfkit` additionally has no AcroForm API.

These are the machine-checkable prerequisites, not a full PDF/UA verdict — but
without them conformance is impossible by construction, so a document generated by
any of these libraries today cannot pass. The only real validator (`veraPDF`) is a
Java binary with no importable npm surface, which is presumably why nobody
notices until an audit.

**Ask:** at minimum, expose document language, title, marked content, and
structure-tree writing. Typst and WeasyPrint are already shipping tagged output
(with their own bugs); the JS ecosystem has no equivalent.

---

## Method note

Each PDF is read back by **two independent engines**: `pdfjs-dist` 4.10.38 and
MuPDF 1.28.6. On the 2026-11-11 run they agreed on **61 of 61 measurable cells,
with zero disagreements** — so F1 and F3 are not artifacts of a single extractor.
`canipdf` reports any cell the two disagree on as `disputed` instead of resolving
it silently.

The font-subsetting crash (F2) needs no referee at all: it throws before a PDF
exists. F4 is read from the raw bytes with a regex, not from either engine.

Remaining step before filing publicly: confirm the RTL ordering on a document
with mixed directional runs, not just a single line. A single-line control is the
weakest form of F1.
